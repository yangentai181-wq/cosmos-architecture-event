# 公開境界ゲート

- 基準日: 2026年9月4日
- 状態: **LIVE VERIFIED。現在ツリーのPages反映を確認済み。過去履歴と共有サービス側の権限は別ゲート**
- 選択: 公開範囲を縮小する案をユーザー承認済み
- 対象: GitHub公開リポジトリ、GitHub Pages、共有Slides / Sheets / Drive / Notion、配布敷地図、外部照会記録

## 判定

公開リポジトリからGoogle Slides / Sheets / Drive / Notionへの直リンクがあり、権利記録のない配布敷地画像もPagesへ掲載されていた。このため、現在ツリーでは公開範囲を次のように縮小した。

- 公開候補のHTML、README、docsから、チーム用Google / Notion共有URLを除去した。
- 権利未確認の `assets/site-detail.png` を削除した。
- 敷地説明は、自作の `assets/site-specific-b-comparison.svg` と文章へ置き換えた。
- チーム内資料はサービス内の名称だけを記し、公開判断はリポジトリ内の文書へ残す。

この変更は「現在のPagesと現在のGitツリーから公開導線・画像を外す」対策であり、完全な履歴消去ではない。

## 現在ツリーの公開条件

次をすべて満たしたためPagesへ反映した。

1. 公開候補にGoogle / Notion共有URLがない。
2. `assets/site-detail.png` がGitツリーに存在しない。
3. 個人連絡先と高確度の秘密情報を検出するテストが通る。

5. 反映後のPagesで、84 / 91 / 99の表示、共有URLの不在、削除画像の404を匿名確認する。

## 継続している境界

- 過去のGit履歴には、削除前の共有URLと配布画像が残り得る。履歴改変は不可逆で影響が大きいため、このPages更新には含めない。
- 共有サービス側の匿名権限は変更していない。接続済みDriveの権限読取が利用できず、既存メンバーのアクセスを保ったまま安全に変更できる状態を確認できなかった。
- 新しいPagesビルドへの匿名取得では旧画像の404を確認した。閲覧端末側に残った過去のローカルキャッシュまでは削除できない。
- `tmp/visualizations/chrome-debug-profile/` にはブラウザのセッション情報が残り得る。Git除外だけに依存してリポジトリ全体をZIP配布したり、`git add -f` で強制追加したりしない。

## ローカルで確定した防止策

- 外部照会文書から個人用メールアドレスを削除し、氏名・詳細所属・返信先・電話番号は送信時だけ入力する。
- `interest/` の確認ボタンを非送信型にし、JavaScriptが動かない場合も回答をURLへ送らない。
- `tmp/`、Pythonキャッシュ、pytestキャッシュ、macOS管理ファイルをGit対象外にする。
- 外部照会台帳には公開可能な最小状態だけを残し、回答者名、受付ID、メール本文、添付、非公開見積は保存しない。

## 外部回答を受けた時の戻し方

1. 受信メール・添付・受付ID・回答者名は、この公開リポジトリへ保存しない。
2. 設計・収支へ必要な内容だけを「確認日 / 組織 / 公開可否 / 事実 / 相手の見解 / こちらの解釈」に分ける。
3. 引用・金額・資料掲載は相手の公開可否を確認し、公開不可なら集約値または条件名だけを記録する。
4. 個人連絡先を含む原文はPersonal SSOTまたは受信元で保持し、このリポジトリへ複製しない。

## この更新に含めないこと

- Google Drive / Slides / Sheets / Notionの共有権限変更
- Git履歴の書換え、force-push
- `tmp/visualizations/chrome-debug-profile/` の削除
- 外部照会、Pages以外の外部送信
