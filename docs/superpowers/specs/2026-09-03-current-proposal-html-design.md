# 現状案共有HTML デザイン仕様

## 目的

グループメンバーが現在の学生寮案を短時間で把握し、企画の論理的なつながりと、各主張の信憑性を検討できる一枚のHTMLを作る。

## 対象読者と利用場面

- 対象読者はCOSMOS Architecture Eventを一緒に進めるグループメンバー。
- 発表用の完成資料ではなく、案を批判的に検討し、次の判断をそろえるための内部資料とする。
- 外部公開やデプロイは行わない。

## 情報設計

ページは「事実 -> 課題 -> コンセプト -> 空間と運営 -> 収益 -> 判断点」の順に読む根拠チェーン型とする。

1. ファーストビューに仮称、要約、計画の前提、現状ステータスを置く。
2. 立地・市場・社会背景の事実から、解くべき課題を導く。
3. コンセプトが各課題へどう応答するかを対応づける。
4. 学生、親、大学、地域への価値と、1階・住居階・屋外・運営の具体案を示す。
5. 正本由来の敷地図を掲載し、図から確定できる情報と未検証の平面計画を分離する。
6. 収益モデルは建設費のみと土地代込みを併記し、評価条件の不整合を目立たせる。
7. 出典一覧と、グループで次に決める論点を最後にまとめる。

## 信憑性の表現

主張を次の3区分で明示する。

- `確認済み`: 配布資料、図面、行政・大学・事業者の公開情報で確認できる事実。
- `解釈`: 複数の事実から企画側が導いた判断。
- `仮説・未検証`: 平面への収まり、戸数、付帯事業利益など、今後の確認が必要な事項。

各重要主張には、根拠となる資料名または外部URLを近接表示する。確認日を2026-09-03として示し、出典が保証していない因果や将来予測を断定しない。

## 視覚設計

- 建築の検討資料らしい、白・濃紺・砂色を基調とした落ち着いた紙面風デザイン。
- 赤橙を「判断が必要」、青緑を「確認済み」、黄土色を「解釈・仮説」の識別色に使う。
- 読み物のヒーローではなく、最初の画面で企画概要と主要数値が見える作業面とする。
- デスクトップでは本文と根拠欄を横並び、スマートフォンでは一列にする。
- モーションに依存せず、印刷時にも情報が欠けない。

## 実装境界

- `proposal.html` の単一HTMLとし、CSSは内部へ記述する。JavaScriptと外部依存は使わない。
- 配布敷地図は非公開の寸法照合だけに使い、公開版には自作の `assets/site-specific-b-comparison.svg` を使う。
- 元資料の数値や主張を勝手に確定事項へ変更しない。
- Google Drive上の正本と `docs/concept-draft.md` / `docs/source-intake.md` を内容の基礎とする。

## 完了条件

- 主要セクション、根拠区分、直接出典、収益の二つの評価条件、未確定事項が揃っている。
- HTML構造検査が通り、リンク・画像参照切れがない。
- 360px相当の狭い画面でも横スクロールを前提としないCSSになっている。
- 外部公開を行わず、ローカルファイルとしてグループへ渡せる。
